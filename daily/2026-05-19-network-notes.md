# 2026-05-19 Network & DeFi Oracle Notes

---

## 一、Network（网络层）

### 1.1 区块（Block）

**区块结构：**
- Block Number（区块高度）
- Block Hash（区块唯一哈希）
- Previous Hash（父区块哈希，链的链接）
- Transactions Root（Merkle Root，所有交易）
- State Root（状态根，Merkle Patricia Trie）
- Timestamp（时间戳）
- Gas Used / Gas Limit

**以太坊区块参数：**
- 出块时间：~12 秒（比特币是 10 分钟）
- Gas Limit：目前约 3000 万（动态调整）

---

### 1.2 共识机制（Consensus）

**两种主流机制：**

| | PoW（工作量证明）| PoS（权益证明）|
|--|-----------------|----------------|
| 原理 | 矿工用算力竞争记账权 | 验证者质押 ETH 竞争记账权 |
| 代表 | 比特币、以太坊经典 | 以太坊（2022年后）|
| 优点 | 安全经过时间验证 | 省电、最终确认更快 |
| 缺点 | 耗电高 | 复杂度更高 |

**以太坊的 PoS：**
- 验证者质押 32 ETH
- 区块由验证者提议（proposer）
- 2/3 以上验证者 attestation（证明）才算最终确认
- 恶意行为会被罚没（slashing）

---

### 1.3 L2（Layer 2）

L2 是建在 L1 之上的扩容方案，继承 L1 安全性。

**为什么需要 L2：**
- L1（Tron等）交易贵（Gas 高）
- L1 慢（12秒出块）
- L2 把大量交易打包，在 L1 结算

**Rollup 两种类型：**

| | Optimistic Rollup | ZK Rollup |
|--|-------------------|-----------|
| 原理 | 假设交易没问题，欺诈时挑战 | 用零知识证明验证正确性 |
| 代表 | Arbitrum、Optimism | zkSync、StarkNet |
| 提现时间 | 7 天挑战期 | 几个小时（直接验证）|
| 计算成本 | 较低 | 证明生成贵 |

**通俗理解：**
- Optimistic = 先送货，买家发现有问题才能退货
- ZK = 卖家提供数学证明，买家即时验证

---

### 1.4 RPC（Remote Procedure Call）

RPC = 你的代码连接区块链节点的接口。

**类比：** RPC = 给区块链打电话的号码
- 节点暴露 RPC 接口
- 你的钱包/DApp 通过 RPC 和链通信

**常见 RPC 提供商：**
- Alchemy（免费 tier）
- Infura（免费 tier）
- QuickNode（付费）
- 自己跑节点

**JSON-RPC 常用方法：**
```javascript
// 读取
eth_blockNumber          // 最新区块高度
eth_getBalance           // 查询余额
eth_call                 // 调用合约（只读）

// 写入
eth_sendTransaction      // 发送交易
eth_sendRawTransaction   // 发送已签名的交易
```

---

### 1.5 链上状态（On-chain State）

**状态（State）：**
- 所有账户的余额
- 所有合约的存储
- Nonce（账户发出的交易计数）

**World State = 所有账户状态的根哈希**

每次新区块 = 状态变化的记录。

**区块浏览器 = 链上数据的展示界面**
- Etherscan（以太坊主网/测试网）
- 各种 L2 有自己的区块浏览器

## 二、DeFi & Oracle

### 2.1 DeFi 基础概念

**DeFi = Decentralized Finance（去中心化金融）**
- 无需中心化机构（银行、券商）
- 代码即规则，规则即法律
- 任何人可自由参与

**核心模块：**
- DEX（去中心化交易所）
- Lending（借贷）
- Stablecoin（稳定币）
- Derivative（衍生品）

---

### 2.2 DEX（去中心化交易所）

**AMM（自动做市商）：**
- 传统交易所 = 订单簿（撮合买卖双方）
- AMM = 流动性池（Liquidity Pool）

**公式：x * y = k**

```javascript
// 流动性池里有两种资产
// ETH 数量 * USDC 数量 = k（恒定乘积）

// 有人买 ETH：
// 他放入 USDC，换出 ETH
// 池子里 ETH 变少，USDC 变多
// 按 x * y = k 自动计算价格
```

**Uniswap = AMM 的代表**

---

### 2.3 借贷

**Compound / Aave = 借贷协议**

```javascript
// 存 ETH 到 Compound
// ETH 作为抵押品（Collateral）
// 借出 USDC（稳定币）

// 抵押率：75%（存 100 ETH 可借 75 USDC）
// 利率：市场决定（供需关系）

```

### 2.4 Oracle（预言机）

**问题：** 区块链是封闭的，不知道链外世界发生了什么。

**例子：**
- 合约要知道"ETH 现在价格"
- 合约要知道"某场比赛结果"
- 合约要知道"某个现实事件发生了"

**Oracle = 链上和链外的数据桥梁**

| | 中心化 Oracle | 去中心化 Oracle |
|--|--------------|-----------------|
| 代表 | 单个数据源 | Chainlink |
| 风险 | 单点故障，可能造假 | 多节点投票，结果更可信 |
| 用途 | 低风险场景 | 高价值合约必须用 |

**Chainlink 工作原理：**
```
真实世界事件
    ↓
Chainlink 节点采集数据
    ↓
节点投票（投票结果共识）
    ↓
数据写入链上
    ↓
合约读取链上数据
```

---

### 2.5 数据源风险

DeFi 合约的风险来源：

| 风险类型 | 例子 | 后果 |
|---------|------|------|
| Oracle 操纵 | 攻击者在交易前操纵价格 | 预言机价格被操纵，清算 |
| 合约漏洞 | 代码 bug | 资金被偷 |
| 流动性风险 | 池子太小，价格滑点大 | 成交价格差 |
| 治理攻击 | 51% 攻击改变规则 | 合约规则被恶意修改 |

**AI Agent 的角度：**
- AI 可以帮检查合约风险
- AI 可以监控 Oracle 数据异常
- AI 可以在清算发生前预警

## 五、常见问题

**Q：L2 和 L1 哪个更安全？**
A：L1 更安全（共识更强）。L2 继承 L1 安全性，但提现有挑战期。

**Q：AMM 为什么叫"自动"做市商？**
A：不需要人主动报价，价格由数学公式（x*y=k）自动计算。

**Q：DeFi 合约被盗了怎么办？**
A：很难追回。所以审计（audit）和风险监控非常重要。

**Q：Oracle 数据能被操纵吗？**
A：可以。Chainlink 这样去中心化 Oracle 通过多节点和聚合降低风险，但无法完全消除。
