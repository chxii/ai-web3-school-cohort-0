# 受限 Web3 助手设计：DeFi 代币兑换与风险检查助手

## 1. 这个助手要解决什么问题

很多普通用户在进行 DeFi 代币兑换（Swap）时会遇到几个问题：

- 不知道应该使用哪个 DEX（如 Uniswap、1inch）
- 不理解 Gas Fee、滑点（Slippage）、授权（Approve）
- 容易误操作，比如授权错误合约
- 不会检查交易是否成功
- 容易被钓鱼网站或假代币欺骗

因此，这个"受限 Web3 助手"专门用于：

**帮助用户安全地完成一次代币兑换流程，但不直接控制钱包、私钥或自动签名。**

AI 只负责：
- 规划步骤
- 检查参数
- 解释风险
- 生成交易说明
- 验证链上结果

AI 不负责：
- 保存或读取私钥
- 自动点击钱包签名
- 自动转账
- 自动授权合约

## 2. Workflow 设计

### 场景

用户希望把 100 USDC 换成 ETH。

### 用户输入

```
我想把 100 USDC 换成 ETH，网络是 Ethereum Mainnet。
```

用户还可能输入：
- 钱包地址
- 最大可接受滑点
- 希望的 DEX
- Gas 预算

---

## 3. AI / Agent 做什么

### Step 1：解析需求

AI 分析：
- 输入代币：USDC
- 输出代币：ETH
- 金额：100
- 网络：Ethereum

### Step 2：查询报价（只读操作）

AI 调用：
- DEX Aggregator API（如 1inch API）
- 链上只读 RPC
- Gas Oracle

AI 返回：

```
预计可获得：0.0312 ETH
当前 Gas：约 $3.20
推荐：使用 Uniswap V3 路由
建议滑点：0.5%
```

### Step 3：风险检查

AI 自动检查：
- USDC 是否是假币合约
- ETH 是否为正确地址
- 当前滑点是否异常
- Gas 是否过高
- 是否存在 Honeypot 风险

AI 输出：

```
风险检查结果：
✓ Token 合约已验证
✓ 流动性正常
✓ 未发现异常授权
⚠ 当前 Gas 偏高
```

### Step 4：生成交易说明（但不签名）

AI 生成：

```
下一步需要你在钱包中完成：
1. Approve USDC 给 Uniswap Router
2. 确认 Swap 交易
3. 检查最终到账 ETH

注意：
- 请确认 Router 地址正确
- 不要授予无限额度（建议仅授权 100 USDC）
```

## 4. Web3 工具或链上步骤

| 步骤 | 工具 / 链上行为 | AI 是否自动执行 |
|---|---|---|
| 获取报价 | DEX API / RPC | ✅ 可以 |
| 检查 Gas | Gas Oracle | ✅ 可以 |
| 检查代币风险 | 区块浏览器 / API | ✅ 可以 |
| 构造交易数据 | SDK / Router ABI | ✅ 可以 |
| 钱包签名 | MetaMask / WalletConnect | ❌ 不可以 |
| Approve 授权 | 链上写入 | ❌ 必须人工确认 |
| Swap 执行 | 链上交易 | ❌ 必须人工确认 |
| 查看交易结果 | 区块浏览器 | ✅ 可以 |

---

## 5. 人工确认点（重点）

以下步骤必须由用户亲自确认，不得由 AI 代为操作：

### 人工确认点 1：钱包连接

用户必须：
- 自己点击 "Connect Wallet"
- 自己选择钱包账户

**AI 不得读取私钥或助记词。**

### 人工确认点 2：Approve 授权

用户必须检查：
- 授权合约地址是否正确
- 授权额度是否为本次交易所需金额（而非无限额度）
- Gas Fee 是否合理

然后手动签名。

### 人工确认点 3：Swap 签名

用户必须再次确认：
- 兑换数量
- 最低收到金额（考虑滑点后）
- 滑点设置
- Gas 估算

然后手动签名。

## 7. 如何验证执行结果

AI 可以帮助用户进行以下验证：

### 方法 1：检查交易哈希

用户提供 Tx Hash：
```
0x8f2a...
```

AI 查询链上：
- 是否成功（Success / Fail）
- 区块确认数
- 实际 Gas 消耗
- 实际收到 ETH 数量

### 方法 2：检查钱包余额

AI 读取公开链上数据：
```
ETH 余额增加：+0.0311 ETH
USDC 余额减少：-100 USDC
```

### 方法 3：验证授权状态

AI 查询：
- 是否仍存在对该合约的授权
- 授权额度是否需要手动撤销（Revoke）

## 8. 风险和限制

### 风险 1：AI 可能引用错误数据源

如果 API 被污染：
- 可能返回错误报价
- 可能推荐恶意 Router

**缓解：** 使用可信 RPC，对合约地址做人工交叉验证。

### 风险 2：用户可能忽略钱包提示

即使 AI 给出警告：
- 用户仍可能签署危险交易（如无限授权）
- AI 无法阻止用户点击"Confirm"

**缓解：** 在每个确认点前加入明确的操作说明和高亮警告。

### 风险 3：链上状态会实时变化

在报价与签名之间：
- Gas 可能上涨
- 滑点可能变化
- 流动性可能减少

AI 的结果仅为"签名时的参考"，不保证最终成交价格。

### 风险 4：AI 无法识别所有新型诈骗

AI 无法：
- 完全识别新型诈骗手法
- 预测 MEV 攻击
- 保证交易一定成功（链上失败因素众多）

### 风险 5：AI 不应保存任何敏感信息

禁止：
- 上传私钥或助记词
- 上传 API Secret / RPC Key
- 在日志中记录钱包相关信息

一旦敏感信息泄露，资产可能立即被盗。

---

## 9. 总结

这个"受限 Web3 助手"遵循一个核心原则：

> **AI 可以辅助决策与检查，但真正的链上控制权必须始终属于用户。**

因此：

- AI 可以"建议"
- AI 可以"解释"
- AI 可以"验证"
- AI 可以"生成交易草稿"

但：
- AI 不能代替用户签名
- AI 不能持有私钥
- AI 不能自动执行链上写操作

这种模式能在提高 Web3 使用体验的同时，尽量降低安全风险。
