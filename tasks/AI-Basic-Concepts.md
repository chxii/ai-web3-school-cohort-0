# AI 基础概念卡片

---

## 1. LLM（大语言模型）

**一句话解释：**
训练过大量文本的神经网络，给你一段文字输入，它能续写/回答/总结，本质是「概率极高下一个该出现什么字」的统计机器。

**具体例子：**
你问「什么是 ERC-20」，它不是去查数据库，而是根据训练时看过的无数文档，生成一段最可能正确的回答。

**常见误区：**
它不是「知道」答案，而是「生成」答案。它可能说得像真的一样但其实是编的（幻觉），尤其在需要精确数字、实时数据的时候最容易出错。

---

## 2. Prompt（提示词）

**一句话解释：**
你发给 LLM 的那段文字，是它唯一的输入来源，怎么写决定它怎么答。

**具体例子：**
```
模糊版：「写个函数检查地址」
→ 输出的代码可能没有异常处理，没有返回值类型

清晰版：「用 Python 写一个检查 ETH 地址格式的函数，输入是字符串，返回布尔值，不要用正则」
→ 约束越清晰，输出越接近你想要
```

**常见误区：**
以为 prompt 一次写好就能用。实际经常要：写一版 → 看结果 → 调整措辞/加约束 → 再试，迭代出来的 prompt 才真正能用。

---

## 3. Context Window（上下文窗口）

**一句话解释：**
模型一次能处理的最大 token 数，超出就「看不见」，包括你问的问题、它之前的回答、所有聊天历史加在一起。

**具体例子：**
你粘了一篇 3000 字的文档进去问问题，结果模型说「我不知道你贴的是什么」—— 很可能文档太长超出了 context window，被截掉了一部分。

**常见误区：**
以为 context window 只能限制「输入」，实际上你问的问题 + 历史对话 + 系统提示词 + 输出的回答，全算在里面。输出太长反而会把前面的内容挤掉。

---

## 4. Agent（智能体）

**一句话解释：**
LLM 加上「判断下一步做什么」的能力，不是你告诉它每一步怎么做，而是它自己决定调用哪个工具、查什么、再做什么，直到给出最终答案。

**具体例子：**
你说「帮我分析这笔交易为什么失败」，Agent 会自己决定：先查交易收据 → 看 revert 原因 → 查合约代码 → 给你结论。它不需要你一步步教它。

**常见误区：**
觉得 Agent 很「智能」就会自动做对。实际上它只是在「模拟」推理过程，可能在某个判断上出错，尤其工具返回的结果不符合预期时它不一定能发现。

---

## 5. Tool Use（工具调用）

**一句话解释：**
让 LLM 能调用外部函数（查网页、读文件、执行代码等），不是光靠训练知识，而是实时获取真实信息或执行真实操作。

**具体例子：**
LLM 训练数据截止到 2023 年，问它「今天 BTC 价格」它只能瞎猜。但接上价格 API 之后，它就能调用 `get_price("BTC")` 拿到真实数据再回答。

**常见误区：**
以为接了工具就 100% 正确。实际上 LLM 只是「决定调用哪个工具」，工具本身有没有 bug、返回的数据格式对不对、调用失败了怎么办——这些都需要你自己处理。

---

## 6. Workflow（工作流）

**一句话解释：**
预设好的一系列步骤，每一步做什么是固定的，通常是：输入 → 步骤A → 步骤B → 输出，和 Agent 的「动态判断」正好相反。

**具体例子：**
你写了一个流程：用户上传合同 PDF → OCR 提取文字 → LLM 提取关键条款 → 输出摘要。每一步做什么是固定的，不会因为合同不同而走不同的分支。

**常见误区：**
把 workflow 和 agent 混为一谈。Workflow 是「写好的剧本」，Agent 是「自己判断下一步」。前者适合标准化任务，后者适合复杂多变的任务。Hackathon 原型常用 workflow 快速出结果。

---

## 7. Human-in-the-Loop（人工介入）

**一句话解释：**
AI 不是全自动跑到底，在关键节点需要人来做决定或确认，特别是涉及真实资源（钱、权限、敏感操作）的时候。

**具体例子：**
你的 Agent 要帮人转账 1000 USDC，它在转之前停下来问：「确认执行吗？」—— 人点确认才真正转出去。这就是 human-in-the-loop，防止 Agent 乱操作造成不可逆损失。

**常见误区：**
以为加了 human-in-the-loop 就安全了。实际上问法很关键：「确认执行吗？」这种问法形同虚设。好的设计是：明确告诉用户要做什么操作、金额多少、风险提示，然后才让用户确认。

---

## 8. Guardrails（护栏）

**一句话解释：**
限制 AI 行为边界的一套规则，比如：不允许它调用某个危险工具、不允许输出特定内容、不允许超过某个阈值。

**具体例子：**
你给 Agent 接了钱包签名工具，但你只希望它查余额，不希望它转钱——加一条 guardrail：「禁止调用 sendTransaction」。这样即使用户让 Agent 转钱，guardrail 会直接拦截并返回错误。

**常见误区：**
觉得 guardrail 是「提示词层面的」，加一句「请不要转钱」就够了。实际上真正有效的 guardrail 需要在系统层/工具注册层实现，不是靠 prompt 约束——prompt 可以被绕过。

---

## 9. Tracing（追踪/链路追踪）

**一句话解释：**
记录一次 AI 请求从头到尾完整过程的日志，包括：调用了哪个模型、传了什么 prompt、调用了哪些工具、工具返回了什么、最终输出了什么。

**具体例子：**
你的 Agent 跑了一个复杂任务结果不对，你想 debug。打开 tracing 日志，发现 Agent 在 Step 3 的时候调用了错误工具，导致后续全错。没有 tracing 的话你根本不知道它「在想什么」。

**常见误区：**
小任务不需要 tracing——对。但一旦接了多个工具、走了多步，出了问题没有 tracing 就只能靠猜。提前埋好 tracing 比你上线后对着日志发呆要高效得多。

---

## 10. AI Coding（AI 辅助编程）

**一句话解释：**
用 LLM 来帮你写、解释、审查、调试代码。能帮你提速，但不可靠，你需要有能力判断它的输出是否正确。

**具体例子：**
你让它写一个排序算法，它可能写得对，也可能写错了一个边界条件。你有代码基础，能看出来它漏了「空数组」的判断；你没有基础，就直接复制粘贴，上线后才发现 bug。

**常见误区：**
把 AI Coding 当「自动驾驶」—— 把需求丢进去，代码出来直接用。正确姿势是「辅助驾驶」：你写一部分，它补一部分，你审核它的输出。Code Review 的能力反而更重要了，因为你要对它写的代码负责。
