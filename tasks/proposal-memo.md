# Verifiable Web3 Research Agent — Proposal Memo

> Z.AI Hackathon · 赛道 Web3 × Long-Horizon Task · 2026-06-06

---

## 一句话说明

**解决什么问题：** 现有 AI 工具做 Web3 研究时只给结论、不给来源，用户无法验证数字真假；而人工核查又得在 Etherscan、Dune、治理论坛之间反复横跳，一次深度调研动辄两三小时。

**给谁用：** 面向散户投资者和 DAO 治理参与者，把一次链上研究压缩到十分钟内完成，且产出报告里的每一条结论都钉死一条可独立复跑的链上证据（Dune Query ID + 区块范围）。

**最小 Demo 跑通哪条链路：** 输入一个自然语言研究问题 → GLM-5.1 自主拆解研究计划、调用 Dune 执行链上查询、SQL 报错时自愈重试 → 前端 Research Graph 实时生长，点开任意结论节点即可展开原始 SQL 与区块数据，全程可观测、可追溯、可独立验证。

---

## 目标用户

散户投资者、Web3 独立研究者与 DAO 治理参与者。他们有基础链上认知（知道 Dune/Etherscan 是什么），需要在投资或投票决策前做深度链上调研，但不愿支付机构级研究工具的订阅费，也没有时间在 Etherscan、Dune、治理论坛之间反复横跳手工拼数据。

---

## 真实场景

**场景 1 — 协议国库链上调研：** 用户想了解某协议国库/大户地址近期的链上动向（如"Aave Treasury 最近的 ETH 转出情况"）。Agent 自主拆解计划、定位相关地址、调用 Dune 查询转账记录，产出带证据引脚的调研结论，每个数字都可点击复跑。

**场景 2 — DAO 治理提案调研：** 用户输入一个 DAO 治理提案，Agent 抓取提案文本与投票数据（Tally）、提取核心参数、再调用 Dune 查询相关历史链上数据，融合多源信息产出提案影响的调研报告。

**场景 3 — 复杂链上趋势调研：** 用户研究某协议的链上趋势（如"Lido 最近一周的 ETH 提款趋势"）。这类查询要落到 Dune 庞杂的 Spellbook schema 上（数千张表、字段类型与链前缀各异），自然语言转 SQL 在首次尝试时很可能选错表或字段类型报错。Agent 能读懂报错、补上对应表的 schema 上下文并重试，直到拿到正确数据，让用户得到可靠且可复跑的结论。

---

## 最小可行功能（MVP）

一条完整链路（Demo 主线）：

```
自然语言研究问题
  → GLM-5.1 自主拆解研究计划（3–5 步，前端可见）
  → 提取链上主体（协议名 → 关联地址）/ 抓取治理或网页内容
  → 调用 Dune 生成并执行 SQL 查询链上数据
  → SQL 失败时触发自愈 Loop（注入 Schema 上下文，最多 3 次，再降级预存查询）
  → GLM-5.1 交叉比对，生成研究结论
  → 前端 Research Graph 渐进渲染完整推理路径
  → 每个结论节点可点击展开原始 SQL、返回 JSON、区块范围
  → 输出研究报告：结论 + 证据引脚列表 + 免责声明
```

三个"证明"是评审重点：**自主性**（计划实时可见）、**可验证性**（节点展开见 SQL + 数据 + 区块）、**自愈能力**（报错 → 注入上下文 → 重试成功全过程可见）。

---

## 验证方式

**前端双看板：**
- **左侧 Research Graph 画布：** 节点从根部生长，颜色区分状态（灰 pending / 蓝 running / 绿 success / 红 failed / 黄 degraded），点击节点打开右侧证据面板。
- **右侧 Agent 执行日志：** 终端风格滚动日志，实时打印每步动作、工具调用参数、返回摘要、错误与重试记录。

**可独立验证的 Web3 证据：**
- Dune 查询 URL（含 Query ID，评委可独立重跑）
- 相关链上地址与交易哈希（Etherscan 可查）
- 报告结论 → 证据引脚 → 原始 SQL + 返回 JSON + 区块范围，逐层可追溯

## 风险边界声明

本项目**只读、不写**：不自动执行链上交易、不管理任何钱包私钥、不向主网写入付费交易、不访问任何付费数据墙内容。链上数据经 Dune 只读获取，治理数据经 Tally 公开 API 只读，网页内容经 Firecrawl 读取公开页面。

报告末尾硬编码免责声明（不可被模型修改）：

> *本报告所有证据链均源自链上公开数据，所有数据引脚可由用户独立验证。趋势判断与结论仅供研究参考，不构成投资建议或法律意见。*

## 赛道选择

选择 **Z.AI 赛道：Web3 × Long-Horizon Task**。

一次链上研究天然是长程任务——它要走完"实体提取 → 地址关联 → SQL 生成 → 链上执行 → 跨源比对 → 结论推演"六个以上有序步骤，每一步输入都依赖上一步产出，不是一次性 API 调用能解决的。GLM-5.1 在项目中承担四个核心智能环节：自主拆解研究计划、动态生成工具调用参数、读懂 Dune SQL 报错并迭代修复、跨数据源交叉推理。其中 **SQL 自愈 Loop**（注入 Schema 上下文、最多重试 3 次再降级）与**目标一致性 Checkpoint**（每步自检是否偏离初始目标、必要时回退重规划）直接体现赛道要求的"持续调用工具、迭代修复"而非一次性生成。整条链路从"用户一句自然语言研究问题"到"带可验证证据引脚的研究报告"，是有明确起点终点的完整 Web3 工作流闭环，全程在前端可观测、可追溯。
